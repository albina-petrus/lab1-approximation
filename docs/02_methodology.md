# Методологія розробки

| Критерій | Agile (Scrum/Kanban) | V-модель | Спіральна |
|---|---|---|---|
| Суть | ітерації, швидка адаптація до змін | послідовні етапи, кожному етапу розробки відповідає етап перевірки | ітерації з аналізом ризиків на кожному витку |
| Для однієї розробниці | церемонії Scrum надлишкові | без зайвого оверхеду | надто громіздка для 2 тижнів |
| Вимоги | змінні | зафіксовані | високо невизначені |

**Обрано: V-модель (полегшена).** Вимоги чітко зафіксовані в методичці; математичне ядро має бути перевірене до побудови інтерфейсу; структура V-моделі (вимоги → проєктування → реалізація → тестування) збігається зі структурою звіту.

| Ліва гілка V (розробка) | Права гілка V (перевірка) |
|---|---|
| ТЗ | Приймальне тестування: усі пункти 4.3 у звіті |
| Проєктування логіки (блок-схеми, ідентифікатори) | Тестування взаємодії модулів (діаграми, ручна перевірка UI) |
| Реалізація модулів (lagrange.js, lsq.js, plot.js…) | Модульні тести (tests.html) |

**Ітерації = коміти:** документація (ТЗ, методологія, проєктування) → структура і дані → інтерполяція → МНК → графічний рушій → контролер і UI → анімації → тести → діаграми взаємодії → виправлення після критичного аналізу → README і звіт.
